SYNOPSIS

SEC-LINE OS (internally designated as zencrypted/os) is a monolithic, zero-trust operating infrastructure designed for high-assurance computing. It synthesizes an ultra-lightweight independent rootfs framework, an immutable Unified Kernel Image (UKI), declarative hardware sandboxing, and strict privilege isolation, eliminating legacy attack vectors.

The Zero-Trust Architecture

SEC-LINE OS is built as a fortress from the ground up. Our architecture is defined by four distinct, uncompromising layers that synthesize to form an unassailable high-assurance computing environment.

1. Verified Hardware Layer

Hardware Trust & Cryptography. Security starts at the bare metal. By completely eliminating vulnerable secondary bootloaders like GRUB, we anchor the OS directly into hardware trust. The system boots via a single, cryptographically signed Unified Kernel Image (UKI) that is evaluated natively by UEFI Secure Boot. Once hardware trust is established, this immutable boot sequence seamlessly decrypts and initializes the storage layer using AES-XTS-PLAIN64 dm-crypt, ensuring no unverified code ever reaches execution.

2. Immutable Runtime Kernel

Hardened Linux & eBPF Observability. Ascending from the hardware, the runtime is governed by a highly tailored downstream derivation of the Linux Hardened kernel. Instead of pursuing raw benchmarks, this layer prioritizes exploit mitigation through strict Page Table Isolation and Kernel Stack Randomization. For visibility, we utilize eBPF tracepoints and auditd, delivering high-fidelity, non-invasive system observability without introducing complex runtime hooking infrastructures.

3. Core Userspace Engine

Deterministic & Minimalist. Above the kernel lies the engine of the operating system—a radically minimized userspace. Discarding the massive bloat of standard GNU utilities and systemd, SEC-LINE OS deploys bitedits/toybox for clean POSIX compliance and openrc for a deterministic, parallel-free service dependency graph. Administrative tasks are tightly controlled by OpenDoas, which boasts a footprint less than 5% of legacy sudo and strictly forbids context persistence between shell instances.

4. Applications & Environment

Sandboxing & The High-Assurance Desktop. Finally, at the highest layer, applications run in an environment of complete zero-trust. Applications lack system-wide visibility and are isolated by default using unprivileged, declarative Landlock LSM rules. The network boundary is fiercely defended by a default-drop nftables core configuration. Graphical sessions are securely routed through seatd and rendered by Claude's Tab Window Manager (ctwm), bypassing modern desktop notification loops to provide a hyper-efficient, secure interaction domain.
